# task-handoff core

## Purpose and complete operating contract

Checkpoint library for `current.md` writes and reads. Its callers are orchestrating
skills — `build-phase`, `build-step`, `plan-expedite`, `user-draft` — that need a durable
checkpoint or an in-window resume. Operators wanting a session transition should use
`/session-wrap`. Bare `/task-handoff` (no flag) defaults to `--resume`.

**task-state contract:** the per-session file model (each session writes only
`sessions/<session-id>.md`; `current.md` is a DERIVED rollup regenerated by
`.claude/hooks/lib/task-state-derive.ps1`), file format, field split, path resolution,
staleness, session identity, and lifecycle are owned by
`.claude/references/task-state-schema.md` — follow
it for every read and write. Safety-critical minimum: resolve the git root via
`git rev-parse --show-toplevel`, never cwd-relative (worktree writes are deleted on cleanup).

None of these modes emits `/compact` or `/clear` — auto-compaction plus the `SessionStart`
re-inject hook handle context in-window (CLAUDE.md § Session wrap & commit discipline).

## `--loop` — checkpoint write

**Cost:** ~5 seconds, no user interaction. Output one line: `"Checkpoint written."`

Write **this session's own file** — `sessions/<session-id>.md`, where `<session-id>` is the
stable opaque ID supplied by the host session-I/O adapter (see the schema doc's
§ Session identity). Read-merge-write *that* file (not the shared `current.md`), applying the
schema doc's per-field append-vs-overwrite rules (it owns that split). In particular, if the
file carries an `**Active project:**` header field (set by `/user-project`), carry it over
**verbatim** — it is a preserve-across-every-write field per the schema doc; silently dropping
it un-pins the session. Because the session owns its file exclusively, the write never contends
with another window — the cross-session clobber is structurally impossible.

Then regenerate the derived rollup so `current.md` reflects the freshest session:

```powershell
$root = git rev-parse --show-toplevel
. "$root/.claude/hooks/lib/task-state-derive.ps1"
Write-DerivedRollup $root | Out-Null
```

`current.md` is a DERIVED rollup (the freshest session wholesale + a listing of the others),
regenerated by the helper — never hand-written, never a write target. **No git commit** —
`sessions/*.md` and `current.md` are gitignored session-local state, so a routine checkpoint
touches no tracked file.

Callers invoke it after each meaningful action — tests pass, a hypothesis is ruled out,
before a new iteration. It should feel nearly zero-cost.

**`--loop --no-commit`** — a backward-compatible no-op alias. It predates gitignored
task-state (when `--loop` committed `current.md` and `build-phase` Step 2e needed the commit
suppressed). Now that a routine `--loop` commits nothing, `--no-commit` and `--loop` are
identical; `build-phase` may keep passing it.

## `--next-task [label] [--next-action-file <absolute-json-path>]` — task-boundary save

**Cost:** ~30 seconds. Durable boundary write when switching tasks within the same goal
(e.g. plan-expedite → build-phase): the same session-file read-merge-write as `--loop` (into
`sessions/<session-id>.md`, then `Write-DerivedRollup`) — the finished task's entries land in
Completed (append); WIP, Next Action, and Status are overwritten to point at the next task
(`[label]`). Then update `MEMORY.md` and commit + push **that** (and any code) — NOT the
gitignored task-state. Scope the add (`git add MEMORY.md <code paths>`); never `git add -A`
(the workspace carries parallel-session churn).

`--next-action-file` is an optional, deterministic transport for a caller-owned multiline Next
Action. Omitting it preserves the legacy label-derived behavior above. When present, require it
only with `--next-task`, require a canonical absolute file path, and read the file exactly once as
UTF-8 JSON without executing or interpolating any value. The file must live outside the Git worktree.
Reject invalid UTF-8, duplicate JSON keys,
unknown/missing keys, a symlink/reparse-point input, or a file inside the Git worktree. The caller
owns deletion after this skill returns; this skill never stages, rewrites, or deletes the file.

The JSON object has exactly this schema:

```json
{
  "schema": "task-handoff-next-action-v1",
  "run_directory": "C:/canonical/absolute/project",
  "preview": null,
  "goal": "/goal \"finish condition\"",
  "action": "/build-phase --plan plan.md --steps 1,2"
}
```

`schema` is the literal shown. `run_directory` must be an existing canonical absolute directory.
`preview` is either null or one non-empty line. `goal` and `action` are non-empty one-line strings.
Reject CR, LF, NUL, other control characters, leading/trailing whitespace, or a field that is not
the declared JSON type. Require a full-string regex match `^/goal "[^"\r\n]+"$` (never a substring
or search match), `action` to begin exactly
`/build-phase `, and a non-null preview to begin exactly `/build-phase ` and contain the standalone
token `--dry-run` exactly once; reject that token in `action`. These checks defend the persistence boundary; the caller remains responsible
for plan-aware selector validation.

Compute lowercase SHA-256 over the UTF-8 bytes of the following fields joined by one NUL byte:
schema, canonical run directory, preview or the empty string, goal, action. Write the decoded
strings into this exact locked multiline `## Next Action` body; omit no labels and add no prose:

```text
<!-- task-handoff-next-action-v1 -->
Digest: sha256:<64-lowercase-hex>
Run directory: <canonical absolute directory>
Preview command:
<exact preview command or NONE>
Action command pair:
<exact goal command>
<exact action command>
<!-- /task-handoff-next-action-v1 -->
```

`NONE` is the literal preview sentinel and cannot be supplied as a command because a real preview
must begin `/build-phase `. The command lines have no Markdown indentation, so their bytes are
preserved. This envelope is the only multiline Next Action shape session-wrap may structurally
split; every other Next Action remains opaque and verbatim. After writing the session file, reread
the locked body, recompute the digest, and fail before `Write-DerivedRollup`, MEMORY update, commit,
or push if it does not match.

Then **keep working in-window**. No manual `/compact` is needed to cross a task boundary.
If a *deliberate* focused reset is genuinely wanted (not the default), emit a
`/compact [focus]` line for the user to type — `/compact` has no programmatic trigger.

## `--resume` — in-window orient

Reads **this session's own** `sessions/<session-id>.md` (falling back to the derived
`current.md` rollup, then the freshest session file, if this session has no file yet — a
fresh window) plus git state, and outputs an orientation block — no window switch. Use after
a compaction or `/clear`. Reading your own session file (not the shared rollup) means a
concurrent window's checkpoint can never surface as *your* Next Action.

```
Resuming [Task field]: [Status]
[Next Action field verbatim]
```

Then proceed with the next action — do NOT ask for confirmation.

---

## `--end` — true session end

Delegates to `/session-wrap`, which triages.
