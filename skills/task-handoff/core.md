# task-handoff core

## Purpose and complete operating contract

Checkpoint library for `current.md` writes and reads. Its callers are orchestrating
skills — `build-phase`, `build-step`, `plan-expedite`, `user-draft` — that need a durable
checkpoint or an in-window resume. Operators wanting a session transition should use
`/session-wrap`. Bare `/task-handoff` (no flag) defaults to `--resume`.

**task-state contract:** the per-session file model (each session writes only
`sessions/<session-id>.md`; `current.md` is a DERIVED rollup regenerated by
`.claude/hooks/lib/task-state-derive.ps1`), file format, field split, path resolution,
staleness, session identity, and lifecycle are owned by
`<repo>/_shared/task-state-schema.md` — follow
it for every read and write. Safety-critical minimum: resolve the git root via
`git rev-parse --show-toplevel`, never cwd-relative (worktree writes are deleted on cleanup).

None of these modes emits `/compact` or `/clear` — auto-compaction plus the `SessionStart`
re-inject hook handle context in-window (CLAUDE.md § Session wrap & commit discipline).

---

## `--loop` — checkpoint write

**Cost:** ~5 seconds, no user interaction. Output one line: `"Checkpoint written."`

Write **this session's own file** — `sessions/<session-id>.md`, where `<session-id>` is the
stable opaque ID supplied by the host session-I/O adapter (see the schema doc's
§ Session identity). Read-merge-write *that* file (not the shared `current.md`), applying the
schema doc's per-field append-vs-overwrite rules (it owns that split). In particular, if the
file carries an `**Active project:**` header field (set by `/user-project`), carry it over
**verbatim** — it is a preserve-across-every-write field per the schema doc; silently dropping
it un-pins the session. Because the session owns its file exclusively, the write never contends
with another window — the cross-session clobber is structurally impossible.

Then regenerate the derived rollup so `current.md` reflects the freshest session:

```powershell
$root = git rev-parse --show-toplevel
. "$root/.claude/hooks/lib/task-state-derive.ps1"
Write-DerivedRollup $root | Out-Null
```

`current.md` is a DERIVED rollup (the freshest session wholesale + a listing of the others),
regenerated by the helper — never hand-written, never a write target. **No git commit** —
`sessions/*.md` and `current.md` are gitignored session-local state, so a routine checkpoint
touches no tracked file.

Callers invoke it after each meaningful action — tests pass, a hypothesis is ruled out,
before a new iteration. It should feel nearly zero-cost.

**`--loop --no-commit`** — a backward-compatible no-op alias. It predates gitignored
task-state (when `--loop` committed `current.md` and `build-phase` Step 2e needed the commit
suppressed). Now that a routine `--loop` commits nothing, `--no-commit` and `--loop` are
identical; `build-phase` may keep passing it.

## `--next-task [label]` — task-boundary save

**Cost:** ~30 seconds. Durable boundary write when switching tasks within the same goal
(e.g. plan-expedite → build-phase): the same session-file read-merge-write as `--loop` (into
`sessions/<session-id>.md`, then `Write-DerivedRollup`) — the finished task's entries land in
Completed (append); WIP, Next Action, and Status are overwritten to point at the next task
(`[label]`). Then update `MEMORY.md` and commit + push **that** (and any code) — NOT the
gitignored task-state. Scope the add (`git add MEMORY.md <code paths>`); never `git add -A`
(the workspace carries parallel-session churn).

Then **keep working in-window**. No manual `/compact` is needed to cross a task boundary.
If a *deliberate* focused reset is genuinely wanted (not the default), emit a
`/compact [focus]` line for the user to type — `/compact` has no programmatic trigger.

## Coordinator packet modes

Use `--coordinator-packet <absolute-json-path>` with `--next-task coordinate-build`
or `--loop` to save the caller's prepared/updated packet and checkpoint its pointer.
Load the shared schema's "Coordinator handoff packet (v1)" section. Validate the
complete caller-supplied fields against actual plan/Git/evidence before the atomic
write; do not infer missing IDs, approval, passing checks or child exit. The packet
path must be under the retained state root and outside builder worktrees. Resolve
that root explicitly from the selected project before any worktree is created;
verify Git common-directory identity rather than treating a builder cwd as durable.

Write the packet first, then this session's own checkpoint with the optional
`Coordinator packet` header and Next Action
`task-handoff --resume-coordinator <absolute-json-path>`. Preserve the pointer during
all later checkpoint writes unless safely detached as described below. Regenerate the rollup through the real available
Write-DerivedRollup helper as usual. If the helper/identity is unavailable, report
required_tool_missing and leave the packet/checkpoint evidence intact; do not invent
a helper, a session ID or a successful rollup. Next-task still commits/pushes only
scoped tracked changes; packet/session state remains private and gitignored.

`--resume-coordinator <absolute-json-path>` selects that exact packet, checks its
schema and repo/plan/ownership bindings, and performs the shared reconciliation
procedure BEFORE proposing or dispatching another assignment. An ambient project
pin or newer session must not redirect this explicit selection. A host ID change
requires verified ownership transfer; create only the new host's own session file,
preserving the prior one. Keep consumed rounds, resolved limits and deadlines.
A missing packet, unresolved child, expired allocation or unproven transfer never
falls back to a fresh build. Checkpoint the concrete status/reason and return it.
When ownership transfer is unproven, do not write the previous owner's packet.
Record the refusal only in the new host's own session file, with its actual ID and
the exact packet locator; if that checkpoint cannot be written, return the refusal
and locator in the response without claiming a saved checkpoint.

Output one compact coordination summary: accepted steps, active/unresolved
assignments, next eligible step or boundary, allocation remaining, evidence locators,
and next owner/action. READY with preparation-only authority returns to the
coordinator without building. With existing build authority and successful execution
preflight, the coordinator may continue via `build-phase --plan <absolute-plan>
--steps <exact-selected-keys> --coordinator-packet <absolute-json-path>`; this is a
same-coordinator call, not a command for the user to retype. Empty selected steps
never omit --steps and fall through to an all-steps invocation.

`--detach-coordinator --next-task <label>` explicitly switches the current session
to a different task or standalone interactive handoff. Follow the shared safe
detachment procedure before overwriting Next Action: reconcile, verify owned work
has exited and durable writes finished, record release and historical locators,
then remove only this session's packet header. A pending unresolved launch blocks
detachment with INCOMPLETE; preserve its pointer and do not start the new task.
Ordinary --loop/render calls never detach implicitly. A --next-task label different
from coordinate-build must use this procedure when a packet header is attached.

## `--resume` — in-window orient

Reads **this session's own** `sessions/<session-id>.md` (falling back to the derived
`current.md` rollup, then the freshest session file, if this session has no file yet — a
fresh window) plus git state, and outputs an orientation block — no window switch. Use after
a compaction or `/clear`. Reading your own session file (not the shared rollup) means a
concurrent window's checkpoint can never surface as *your* Next Action.

```
Resuming [Task field]: [Status]
[Next Action field verbatim]
```

Coordinator resume requires this session's own checkpoint or an explicitly selected
packet/session. If only an ambient rollup/freshest fallback has a Coordinator packet
header, show its locator for explicit selection; do not adopt or dispatch from it.
If the explicitly selected checkpoint carries a Coordinator packet header, route through
`--resume-coordinator` first; do not blindly replay a recorded build command.
Otherwise proceed with the next action - do NOT ask for confirmation.

Delegates to `/session-wrap`, which triages.
