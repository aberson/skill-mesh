Agent defaults to inspect

D1 · Source dependency

Use a pinned local checkout initially

What: configure an explicit source root and immutable commit for helpers and calibration data.

Why: restore this host without restarting raw-file installer ownership work. Installed files alone remain insufficient.

Tweak: require installed-only operation; that changes the delivery design and scope.

D2 · Aggregate correctness

Fix the aggregate before lifting the halt

What: validate the complete expected set, block uncertainty, and preserve real invocation/plan metadata.

Why: calibration replay cannot detect these live reducer defects. Existing runtime/full and absence-of-thing evidence remain supported.

Tweak: choose a different explicit uncertainty representation; it must remain unable to advance.

D3 · Host contract amendment

Use capacity-limited waves and an observable deadline

What: prepare all six prompts from one frozen candidate, then run fresh siblings in waves of up to three on this four-slot host. Where first-token timing is unavailable, measure a 180-second completion deadline with one retry after 30 seconds.

Why: the host cannot run six reviewers simultaneously or report their first-token times. The stricter completion deadline can reject a healthy slow reviewer; it is not claimed to be first-token parity.

Tweak: choose a different explicit completion budget, or retain the native timing requirement and use a host that exposes it.

D4 · Bounded bootstrap

Review the first two steps through the pinned source protocol

What: the parent runs six full-depth independent lenses from the pre-implementation contract, validates every result, and rejects an unsafe old-reducer PASS. It preserves the normal sidecar, prior-round evidence, and private build verdict authority.

Why: the unimplemented adapter cannot be its own prerequisite. The protocol expires after Step 121 is qualified and never substitutes for the consumer’s normal deep-review calls.

Tweak: use a real supported Claude native review when available. The shell router’s stub is not an executing fallback.

D5 · Lane boundary

Restore code-deep first

What: leave Codex runtime/full deep requests explicitly unsupported.

Why: the blocked consumer requires the code-deep lane. Ordinary gauntlet full/runtime behavior is unchanged.

Tweak: add a separately specified runtime mapping and acceptance surface.

D6 · Evidence boundary

Separate calibration from live acceptance

What: preserve the existing gold labels and score timestamps; observe real reviewers in Step 123.

Why: replayed scores do not establish live judge quality or host behavior.

Tweak: broaden the live evaluation corpus as a separate quality study.

Not in this version

Raw package delivery, installer/WAL redesign, old RD resumption, model-quality benchmarking, local-model reviews, a scheduler, or changes to the paused catalog and handoff worktrees.

Practical limits

  • The loaded adapter and source checkout must remain a matched immutable pair; a mismatched upgrade fails visibly.
  • The bootstrap and timing amendments are substantive proposal choices. Missing timing/cancellation/isolation capability still stops execution.
  • Shared filesystem access is not an operating-system sandbox. The plan preserves parent-only authenticated advancement and audits reviewer mutations.
  • A failed live case produces evidence to triage; it is not retried unchanged until a favorable result appears.
