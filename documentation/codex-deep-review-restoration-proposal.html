The acceptance condition

Every row must pass independently on Codex and Claude, using the same certified release and fixture revision.

  1. W1: fresh native discovery, matched profiles/support assets and real dependencies.
  2. W2: a real developer produces the ordinary-full candidate; eight reviewers reject its planted defect.
  3. W3: a fresh correction passes the repeated gates and runtime review, merges and checkpoints.
  4. W4: a new native coordinator selects the intended checkpoint despite newer unrelated task state.
  5. W5: six deep lenses reject a second defect, then accept its correction using the exact prior sidecar.
  6. W6: normal cleanup, final checkpoint and authenticated advancement complete.

A missing host, missed defect, incomplete evidence or failed resume leaves the task pending. These rows prove this bounded workflow; they do not claim every catalog skill works.
