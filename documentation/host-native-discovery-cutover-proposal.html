Operator proposal

Host-native discovery, without the legacy ambiguity

Make the public skill-mesh package the actual source used by both hosts, migrate the private coding-root consumer with rollback, and keep workspace instructions separate from skill discovery and explicit router dispatch.

What I heard

The GPT path should be explicit

Copilot should discover generated GPT adapters from .copilot/skills, not succeed only because this runtime can see the historical Claude-owned tree.

The Claude path should stay native

Claude Code should discover generated Claude adapters from .claude/skills. Model choice must not determine the skill directory.

Instructions are a separate concern

CLAUDE.md and AGENTS.md are host instruction adapters, not skill catalogs. Private content remains in coding-root.

Why this shape

The public product repository is clean and canonical, while the live consumer still uses an old router, an ordinary .claude/skills directory, and no .copilot/skills install. A direct forced overwrite would erase evidence and weaken the installer's ownership model. The plan therefore adds inspect, backup, transactional migration, temporary-home acceptance, and only then live cutover.

Delivery timeline

Step 42 - Lock the authority map

Document and test the distinct roles of workspace instructions, native skill discovery, and router dispatch.

Step 43 - Inspect before touching

Add a read-only report for ownership, link type, legacy shadows, router version, instruction files, and missing provider profiles.

Step 44 - Migrate as one transaction

Require an external backup directory, install Claude and GPT together, verify both, and restore the original home if either side fails.

Step 45 - Publish the consumer handoff

Replace stale Step-41 guidance and define the separate private instruction cleanup.

Steps 46-47 - Prove, then cut over

First run both real hosts against a temporary home. Only after rollback rehearsal passes, migrate the clean coding-root consumer and capture each discovered path.

Not in this phase

  • Publishing private rules, hooks, memory, or project adapters.
  • Changing skill behavior, model mappings, reviewer gates, or authentication.
  • Using AGENTS.md as a skill registry.
  • Deleting legacy files before both real hosts pass and rollback is rehearsed.

Risks that remain visible

  • Host opacity: a host may not reveal which instruction file it loaded; reports must label observed versus inferred facts.
  • Dirty consumer: live migration waits until parallel coding-root work is parked on a clean branch.
  • Private backups: payloads stay outside the repository and release artifacts; reports contain only relative paths and hashes.
