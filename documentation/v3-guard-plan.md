An agent that is asked to make a small skill change reads one test rule, "the full suite is the DONE gate", and runs it. It does not say that the suite takes 3 to 4.5 hours, and it does not ask. So the cause is mostly what Codex is told, not how it treats an explicit instruction (on 10/29 it obeyed "don't over test" within 4 seconds).

## Reconciliation with the catalog gate plan

The accepted catalog gate plan (`catalog-gate-plan-2026-11-12.md`, issues #244 to #255) is not edited here. This section states where the adopted testing rule changes its premise, and gives a default for each point.

1. **Premise changed: what the done gate is.** The catalog plan chooses a suite by what a change touches: a change that touches only catalog content gets the catalog gate, anything else falls through to `full` (the repo-root suite), and its Phase 2 makes that selector the standing done gate. Under the adopted rule no step or merge is gated by a full suite at all: every change runs focused tests plus the quick repo-wide checks, and the full sweep runs once per release, in the background. So `full` stops meaning "a blocking multi-hour run at DONE". **Default:** the done gate for every change, catalog or not, is the per-change pack (Step 5) plus the focused set for what the change touches. The catalog gate's class table and selector are kept and re-read as the chooser of that focused set (a `catalog` result means the catalog tests are the focused set; a `full` result means the focused set is larger and named, not that the full suite runs).
