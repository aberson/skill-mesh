# Cross-family execution-seam runbook

This runbook executes Goal A Step 77. It compares two executable mechanisms in two directions:

- `manual-saved-handoff`: prepare a sealed handoff, stop for an operator check, then invoke the reviewer;
- `reviewer-only-dispatcher`: prepare and invoke the reviewer in one bounded run;
- `claude-to-gpt`: use `gpt-5.6-terra` as the reviewer; and
- `gpt-to-claude`: use `sonnet` as the reviewer.

The fixture is synthetic. A direction names the simulated origin role and the real reviewer role.
It does not prove that a Claude-family or GPT-family model built the candidate.

`manual-now-automation-deferred` is a Gate A policy option. It reuses the evidence from a successful
`manual-saved-handoff` series. It is not a third model run and must not get a new Step 77 series ID,
latency, token count, cost, or model claim.

## Safety boundary

Run this procedure from a quiescent PowerShell window. Close active Claude and Codex sessions first.
The probe takes one full candidate-bound HMAC snapshot of the protected live state before the
reviewer and one after it. An incomplete baseline stops before the host starts. Any before-and-after
delta is `AMBIGUOUS`, including Codex database or session activity. The probe retains the reviewer
evidence after such a delta and never reports that no live mutation occurred.

Each raw snapshot file has a separate 64 MiB cap. The general evidence-file cap remains 16 MiB.
The snapshot still stops at 100,000 records, 600 seconds, or any incomplete or changing record.

The experiment:

- creates only the named disposable fixture root and evidence directory;
- reads one saved credential file from the target reviewer's live home and copies it to a disposable home;
- never writes to either live home;
- does not call the production router;
- does not use Copilot, a direct API fallback, another model, or another host as fallback;
- requests medium reviewer effort with Claude `--effort medium` or Codex
  `-c model_reasoning_effort="medium"`, as applicable;
- supplies no fallback option to either host;
- passes the same sealed prompt bytes to each reviewer; and
- retains raw evidence while removing the disposable home after the attempt.

The target reviewer receives the sealed prompt as one positional argument. The candidate-owned Job
Object helper gives the target process NUL standard input. `InvokeSavedHandoff` reads and validates
the saved request before passing those exact bytes. `Run` passes the same generated bytes directly.

For every non-WhatIf action, the wrapper exports the exact committed Step 76 files and the two
reviewed Step 74 safety helpers into one temporary candidate-runtime tree. Python runs only those
exported bytes. The wrapper removes that tree before it forwards the probe's single JSON result. A
cleanup failure suppresses the child result and produces one fail-closed outer result instead.

Do not continue when a `-WhatIf` call reports a rejection, a path overlaps a repository or live home,
the candidate SHA differs, credential authority is unclear, or a previous target path already exists.

## One-time values

Fill in `RepoRoot` and the committed Goal A Step 76 candidate SHA recorded in `plan.md` and the
external evidence index. This is not the seeded repository's inner commit. Do not create a fixture
or evidence leaf yourself. The probe owns those paths with create-new semantics.

```powershell
$RepoRoot = '<absolute Goal A worktree path>'
$GoalAId = 'goala-20260814T021737Z-1b5ec416'
$CandidateSha = '<40-character lowercase Step 76 candidate commit>'
$AttemptId = 'a0'
$ReviewerTimeoutSeconds = 600

$Runner = Join-Path $RepoRoot 'experiments\recovery\run-cross-family-probe.ps1'
$LiveClaudeHome = Join-Path $env:USERPROFILE '.claude'
$LiveCodexHome = Join-Path $env:USERPROFILE '.codex'
$HomesRoot = Join-Path (Join-Path $env:LOCALAPPDATA 'SkillMesh\Homes') $GoalAId
$EvidenceRoot = Join-Path (Join-Path (Join-Path $env:LOCALAPPDATA 'SkillMesh\Evidence') $GoalAId) 'cross-family'

function New-CrossSeriesId {
    param(
        [Parameter(Mandatory = $true)][string]$Direction,
        [Parameter(Mandatory = $true)][string]$Mechanism
    )
    $stamp = [DateTime]::UtcNow.ToString('yyyyMMddTHHmmssZ')
    $suffix = ([Guid]::NewGuid().ToString('N')).Substring(0, 8)
    return "cross-$Direction-$Mechanism-$stamp-$suffix"
}

if (-not (Test-Path -LiteralPath $Runner -PathType Leaf)) {
    throw "Runner not found: $Runner"
}
```

The allowed initial attempt IDs are `a0`, `a1`, and `a2`. One byte-identical rerun may add `-r1`,
for example `a0-r1`. Use a new run ID for each direction-mechanism series. Keep every attempt.

## Manual saved handoff: Claude role to GPT reviewer

Create the series values. Both target leaves must be absent before `Prepare`.

```powershell
$Direction = 'claude-to-gpt'
$Mechanism = 'manual-saved-handoff'
$RequestedReviewerModel = 'gpt-5.6-terra'
$RunId = New-CrossSeriesId -Direction $Direction -Mechanism $Mechanism
$FixtureRoot = Join-Path $HomesRoot "$RunId-$AttemptId"
$EvidenceDir = Join-Path (Join-Path $EvidenceRoot $RunId) $AttemptId
```

First inspect the zero-write plan.

```powershell
& powershell.exe -NoLogo -NoProfile -NonInteractive -ExecutionPolicy Bypass -File $Runner `
    -GoalAId $GoalAId -Action Prepare -Direction $Direction -Mechanism $Mechanism `
    -FixtureRoot $FixtureRoot -CandidateSha $CandidateSha -EvidenceDir $EvidenceDir `
    -RunId $RunId -AttemptId $AttemptId -LiveClaudeHome $LiveClaudeHome `
    -LiveCodexHome $LiveCodexHome -RequestedReviewerModel $RequestedReviewerModel `
    -CredentialMode copy-file -ReviewerTimeoutSeconds $ReviewerTimeoutSeconds -WhatIf
if ($LASTEXITCODE -ne 0) { throw 'Prepare WhatIf failed' }
```

Prepare the sealed handoff. This action must not start a reviewer.

```powershell
& powershell.exe -NoLogo -NoProfile -NonInteractive -ExecutionPolicy Bypass -File $Runner `
    -GoalAId $GoalAId -Action Prepare -Direction $Direction -Mechanism $Mechanism `
    -FixtureRoot $FixtureRoot -CandidateSha $CandidateSha -EvidenceDir $EvidenceDir `
    -RunId $RunId -AttemptId $AttemptId -LiveClaudeHome $LiveClaudeHome `
    -LiveCodexHome $LiveCodexHome -RequestedReviewerModel $RequestedReviewerModel `
    -CredentialMode copy-file -ReviewerTimeoutSeconds $ReviewerTimeoutSeconds
if ($LASTEXITCODE -ne 0) { throw 'Prepare failed' }
```

Operator checkpoint: stop here. Confirm that stdout says `PREPARED` and `host_started` is `false`.
Inspect the prepare manifest and the sealed receipt, payload, and request artifacts in `EvidenceDir`.
`Prepare` does not publish the final experiment report. Confirm the run identity, candidate SHA,
prompt hash, requested reviewer, and no-fallback policy. Do not proceed on a mismatch.

After that separate check, inspect the invoke plan and then run it.

```powershell
& powershell.exe -NoLogo -NoProfile -NonInteractive -ExecutionPolicy Bypass -File $Runner `

    -RunId $RunId -AttemptId $AttemptId -LiveClaudeHome $LiveClaudeHome `
    -LiveCodexHome $LiveCodexHome -RequestedReviewerModel $RequestedReviewerModel `
    -CredentialMode copy-file -ReviewerTimeoutSeconds $ReviewerTimeoutSeconds -WhatIf

```

## Read the result

The wrapper preserves the probe's stdout, stderr, and exit code. Stdout is one compact
`skill-mesh.cross-family.probe-result.v1` JSON object.

| Status | Meaning |
|---|---|
| `WHAT_IF` | Validation and the zero-write plan completed. No owned target was created. |
| `PREPARED` | The manual handoff was sealed. No reviewer started. |
| `COMPLETE` | The requested reviewer action ended and the report and manifest were published. |
| `REJECTED` | Request or preflight validation stopped before output ownership began. |
| `INCOMPLETE` | Output ownership began, but complete evidence could not be published. |

Exit `0` means the requested action completed and its evidence was published. It does not mean the
experiment result is `PASS`. Exit `2` means preflight rejection before owned output. Exit `3` means
an internal or incomplete run after output ownership began.

The report result has a separate meaning:

- `PASS`: all required observations have trustworthy evidence;
- `PARTIAL`: the seam worked, but a non-safety observation is unavailable;
- `FAIL`: a required behavior failed and the evidence identifies the failure; and
- `AMBIGUOUS`: the evidence cannot distinguish plausible explanations or prove identity or safety.

The requested model comes from the command. It is not resolved-model proof. Use only structured host
metadata for the resolved model. When the host does not report it, record `unavailable` or
`unverified`; never copy the requested value into the resolved field. Adapter names are not model
evidence. The report must also retain the redacted argument record that proves the applicable medium
effort setting and the absence of a fallback option. Reviewer model identity is load-bearing here.
Missing or unverified resolved identity makes the overall result `AMBIGUOUS`, even if the seam works.

The host interfaces do not reliably report fallback attempts. The report records attempt metadata
as `unavailable` while the command record proves that fallback was not configured. Any observed
fallback makes the result `AMBIGUOUS`.

Retain the report, raw stdout and stderr, invocation plan, process-containment record, root exit code,
receipts, candidate-before and candidate-after identity records, and SHA-256 manifest. These files
stay under the returned evidence directory. Cleanup may remove only the named disposable home and
fixture content that the report marks removable. Never remove the evidence directory. Stop and retain
evidence when cleanup cannot prove an empty process tree, when a live home changes, when candidate
identity changes, or when a credential or source locator is unclear.
