Skill Mesh proposal - publication 1

Provider-neutral by construction

Move shared contracts and routing out of Claude-owned paths, generate native adapters for each host, and make the public repository match the product it claims to provide.

47 portable skills 2 first-class cloud providers 9 build steps 3 explicit Claude-native exclusions

What I heard

The product still reads as Claude-first

Rename and restructure it around the shared workflow rather than treating GPT as an appendix.

The auth story is wrong

GitHub Copilot authentication is a supported GPT transport; a direct OpenAI API key is optional, not universal.

The source tree communicates ownership

Shared cores, mappings, and routing should not be canonically rooted under .claude.

Matching the active model matters

Claude hosts should discover Claude adapters and GPT hosts GPT adapters without a silent Claude default.

Why this shape

The current internal implementation has paired wrappers and shared cores, but the public repository publishes a flattened Claude-oriented export. The proposed shape makes the public repository authoritative and treats host layouts as generated compatibility products.

Risks to watch

Host metadata is incomplete

Use installation-time binding and fail explicitly when runtime detection is ambiguous.

Two repositories drift

Make one canonical, generate consumers, and compare manifest hashes in release gates.

Compatibility paths break

Keep tested shims and exercise Windows junction installation before publication.

Fallback hides provider failure

Retain exit code 2, fallback disclosure, adapter/core identity, and telemetry attempt roles.
