What I heard

You want fewer context losses and repeated mistakes first, with skill improvements automatically trialed in isolation before you review them. You asked for smaller projects, less unnecessary engineering/testing, and a clear fit with the builds already underway.

This revision incorporates that direction. It retains all six investigations while removing their earlier dependency chain.

Why this shape

Reuse the known work

M1 Step 127 already owns durable checkpoint selection. AP already owns hygiene attribution. CL already owns canonical skill mutation. Each keeps its current contract.

Keep the unknown visible

Codex's evolve adapter does not map the scoring workflow. Qualify one real independent route before estimating its integration. Isolated agents alone do not prove it.

Cut prerequisites

Capture does not need a new checkpoint journal, section parser, transcript collector, runtime package or dashboard.

Prove the behavior

Use named failure cases and one complete observed cycle. Preserve repository gates and independent grading; remove arbitrary day/session/run quotas.

Review still follows actual risk. Full repository/provider gates and real-host acceptance remain; changed hooks retain smoke/self-test.

What still needs proof

  • Build preparation: the capture slice needs exact marker/command/path bounds and numbered implementation/acceptance steps. The portfolio is reviewable, not directly executable.
  • Evaluator capability: a real independent route is unqualified. An unavailable result preserves the value of capture and triggers separate adapter scoping.
  • Coverage: explicit capture misses unreported mistakes. Marker counts do not measure an error rate.
  • Resume: M1's explicit selection does not certify every default hook path.
  • Evidence: keep private records minimal. Tombstones do not erase retained bytes.

Technical review · Fresh-context check. Both distinguish scope review from executable build readiness.
