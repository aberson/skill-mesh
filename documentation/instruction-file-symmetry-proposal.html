Instruction-file symmetry

Make AGENTS.md the shared content file, keep CLAUDE.md as the Claude-compatible import, and stop lifecycle skills from silently recreating two competing instruction files.

01 · What I heard

One content copy, safe on both hosts

Phase IS fixes the catalog before the wider portfolio begins flipping project instruction files.

1Invert only when safe

On a greenfield project, author the seven sections in AGENTS.md and emit exact @AGENTS.md pointer bytes in CLAUDE.md.

2Preserve existing projects

A substantive legacy CLAUDE.md keeps working as it does today. No migration happens under this plan.

3Repair the whole catalog

Re-enumerate cores and provider adapters, then repoint every project-instruction reader or writer the evidence proves unsafe.

4Prove delivery, not just prose

Add package-integrity gates, build generated profiles, install to a scratch home, and exercise the five behavior rows on real hosts.

02 · Why this shape

The hosts resolve project instructions differently

The plan's dated measurement against codex-cli 0.147.0 found that Claude expands an @AGENTS.md import while Codex expands no imports. Therefore the file Codex reads must contain the content itself.

Codex reads AGENTS.mdNo import expansion means the content must live there.
→
Claude sees CLAUDE.mdThe exact @AGENTS.md line imports the same content.
→
One maintained bodyLifecycle skills refresh the substantive file without restoring duplication.
03 · Delivery sequence

Ten steps, four bounded stages

Each stage unlocks the next. Scratch installs and projects remain disposable; consumer repositories stay untouched.

Contract and lifecycle writers · Steps 100–102

Put the three-state contract and five-row matrix in one owning core; make plan-init and repo-update implement it.

Afterwards: run Step 103's full classification before choosing any remaining reader edits.

Catalog audit and repair · Steps 103–105

Classify every relevant core and provider hit, repair proven project readers, and make context-slim inversion-aware without changing its ancestor anchor.

Afterwards: run Step 106 to enforce both the write surface and single-owner contract.

Mechanical gates and documentation · Steps 106–107

Land the two package-integrity gates, prove six planted defects red, vendor the host measurement, and update the suite-count owner only after measuring.

Afterwards: powershell -File tools/build-distributions.ps1 -Provider all.

Scratch delivery and operator proof · Steps 108–109

Install the Claude profile into a disposable home, exercise the behavior matrix in a disposable project, and verify Codex input plus Claude import resolution.

Afterwards: record operator feedback and only then proceed to /repo-sync.
