## 1. What This Is

Proposal: docs/plan-redline/dev-core-companion-plan-2026-11-18-proposal.html (in the coding-root repository, where this copy was prepared)

A new Skill Mesh user should get the skills **and** the small tools those skills call with one
install command. Today they get only the skills. Each utility needs its own checkout or
`uv tool install`, plus `DEV_UTILITIES_ROOT` and a restart, so in practice only Passing Notes ends
up on PATH. Without a tool, its skill falls back silently. The clearest case is Drift Ranger, which
seven skills call; without it a new user always gets the "Intent fallback".

The core companion is a **distribution layer, not a merge**:

- **Separate repositories.** Every utility keeps its own repository, issues, tests and release
  schedule (portfolio decisions P-7 and D3 stand).
- **One manifest.** Skill Mesh gains `config/companions.json`, listing each member, its pinned tag,
  its callers and the contract version the skills read.
- **One installer option.** `-Companions core|all|none` installs the selected members, their skills
  and their hooks. The default becomes `core` only after fresh-user acceptance (Step 19).
- **Fail open.** Every call to a companion still fails open: a missing or mismatched tool costs at
  most one advisory line and never blocks.

**Evidence of use (2026-11-18, usage page section 2).**

- **Daily:** passing-notes (13 installed skill files plus its user-level Stop hook) and tripwire
  (PreToolUse `Bash|PowerShell` hook, 13,816 shadow rows since 2026-10-22). Also drift-ranger
  (7 skill cores; say-no-more wrote events on 2026-11-17) and switchboard's registry, which
  generated all 14 `~/.claude/agents/role-*.md` files.
- **Never run:** find-again (no state, no index).
- **Not wired:** heads-up, changed-check, paper-trail, same-page, mesh-lens.

**Prerequisites for a user of the finished install.** Skill Mesh itself needs Windows with
PowerShell 5.1 or later (`skill-mesh/README.md:527`). `-Companions` adds three:

- Python 3.12 or later (the highest member floor: tripwire, find-again and switchboard declare
  `>=3.12`; passing-notes `>=3.11`);
- `uv`, the Python package and tool manager, whose `uv tool install` puts a command on PATH;
- Git.

The installer checks for all three and prints `skipped: missing <tool>` instead of failing.
Claude Code is the only host whose hooks v1 registers. No server or account is needed, and the
judge offload's local model server is never required.

**Terms used in this plan.**

- **Skill Mesh:** the multi-host skill catalog and installer in the `skill-mesh` repository.
  `install-skill-mesh.ps1` is its installer. The **change pack** (`python tools/change_pack.py`) is
  its per-change gate.
- **Utility / member:** a small local CLI tool in its own public repository (passing-notes,
  tripwire, drift-ranger, find-again, switchboard, ...). A **member** is one listed in the companion
  manifest at ring `core` or `optional`.
- **Advisory-call convention:** `<coding-root>/.claude/references/advisory-call-convention.md`, the
  one owner of how skills call utilities. Every call is bounded, fails open and never blocks.
- **Portfolio decisions:** in `<coding-root>/docs/plan-reviews/2026-07-25-utility/DECISIONS.md` and
  `docs/utility-project-proposal.html`. **P-7:** no utility depends on another. **D3:** each utility
  has its own repository. **P-4:** readers refuse a newer `schema_version` with a clear error.
- **Phase PROD:** an older, parked Skill Mesh workstream for a stable production toolchain. Only its
  lessons carry over.
- **Phase HE:** the coding-root hook-enforcement plan (`docs/hook-enforcement-plan.md`), which edits
  the tripwire hook. **Step M1** is its operator shadow-soak decision.
- **Toolkit program / hookup rail H00-H08:** `<coding-root>/plan.md`, which owns when each utility
  gets wired into skills. H01 is Heads Up, H03 Same Page, H04 Changed Check, H05 Paper Trail and
  H07 Mesh Lens.
- **V4-2:** the Skill Mesh v4 row for measured model pins (switchboard and measure-twice).
- **Role files:** `~/.claude/agents/role-<role>.md` and `~/.codex/agents/role-<role>.toml`,
  generated by `switchboard apply` from `switchboard/registry/models.json`. They set the model and
  effort for each sub-agent role.
- **TW-SEC-001, TW-GIT-001, TW-GIT-003:** tripwire rules. They cover printing a secrets file, broad
  `git add -A`/`.` staging, and destructive git (`reset --hard`, `push --force`,
  `checkout -- <path>`).
- **Lane, card, note:** Passing Notes' coordination objects between agent windows.
- **build-phase / build-step:** Skill Mesh's orchestrator for a plan's steps, and its single-step
  builder with independent reviewers. `--reviewers deep` routes review to `review-deep`, the
  full six-lens reviewer.

**Why these tools.** The installer extends the existing PowerShell `install-skill-mesh.ps1`, because
that is how every Skill Mesh host is installed today. The manifest tooling is Python
(`tools/companions.py`), like the rest of skill-mesh's `tools/`. JSON matches the existing
`config/*.json` manifests. Members install with `uv tool install`, because every member is a
Python package and uv installs each one in its own isolated environment with its command on PATH,
with no checkout. uv is a new prerequisite for `-Companions` only, not for a skills-only install.

## 3. Membership rule

A utility is a **member** (ring `core` or `optional`) only when all four of these hold:

1. **It has a caller.** A skill or hook in a shipped Skill Mesh release calls it, and the manifest
   names that call site by path. A name match in prose, evals or tests does not count.
2. **It is public.** It installs from a public repository with
   `uv tool install "git+https://github.com/<owner>/<slug>@<tag>"`.
3. **It has a pinned tag.** The tag has passed Skill Mesh's contract test for that member (Step 11).
4. **It meets the standard.** It passes `utility-standard check` at the public profile (CC-D9).

**Rings.**

- **Core** members install with `-Companions core` (the default after Step 20).
- **Optional** members install only with `-Companions all`. The manifest carries their setup steps,
  which are printed and never run.
- **Candidates** are listed for visibility and never installed. A candidate is promoted by editing
  its manifest row once its hookup ships in a release.

## 4. Companion manifest shape (`config/companions.json`, schema_version 1)

Top level: `schema_version` (int, 1) and `members` (list, sorted by `slug`). Readers accept older
versions and refuse newer ones with an explicit error (portfolio decision P-4).

| Field | Type | Rule |
|---|---|---|
| `slug` | str | repository name; unique; `[a-z0-9-]` |
| `ring` | enum `core` \| `optional` \| `candidate` | `candidate` is never installed |
| `repo` | str | `https://github.com/<owner>/<slug>`; required for core/optional |
| `tag` | str or null | semver tag matching `^v\d+\.\d+\.\d+$`. Null means "unreleased": allowed in the tree, skipped by the installer, refused by `verify --release` |
| `cli` | str | command name expected on PATH after install (e.g. `drift-ranger`) |
| `health` | list[str] | argv run after install; exit 0 = healthy. It must exist at the pinned tag (checked by Step 11). tripwire, drift-ranger and switchboard gain `--version` in Steps 6, 3 and 12; passing-notes and find-again already have it |
| `contract` | object | `{ "name": str, "schema_version": int }`: the payload version the skills read |
| `callers` | list[str] | at least 1 for core/optional. Each entry is either a skill-mesh repo-relative path, which Step 1's `verify` checks exists, or `member:<path>` for a call site in the member's own repository (tripwire's packaged hook), which Step 11's contract suite checks at the pinned tag |
| `skills` | object or null | `{ "installer": [argv], "uninstaller": [argv], "names": [str] }`: the member's own skill installer. Skill Mesh never copies those files itself |
| `setup_write` | object or null | `{ "install": [argv], "uninstall": [argv] or null }`: a member-owned writer with its own ledger, run after install (switchboard `apply --write`). Never used to enable an optional feature such as the judge offload |
| `hooks` | list | each entry is one of two kinds (below) |
| `setup` | list[str] | human-readable optional-ring setup steps, printed, never run |
| `candidate_note` | str or null | for candidates: the hookup that promotes it (e.g. "Toolkit H04") |

**Hook entry kinds.**

- **`kind: "file"`** (tripwire). Fields: `name` (`[a-z0-9-]`, used in the installed file name), `host`, `event`, `matcher`, `locate` (argv printing the
  packaged hook file's absolute path, e.g. `["tripwire","hook","path","--host","claude"]`),
  `timeout`. The companion copies the file and merges the settings entry itself (Step 10).
- **`kind: "member"`** (passing-notes). Fields: `host`, `event`, `install`, `uninstall` and `check`
  argv. Each takes `--settings <path>`, for example
  `["passing-notes","hook","install","--settings","{settings}"]`. The member owns its own settings
  entry; the companion only runs the member's commands and records the result (Step 10).

**Argv substitution tokens.** The installer replaces exactly two tokens inside manifest argv
entries, and nothing else: `{home}` becomes the absolute `-Home` directory, and `{settings}` becomes
`<home>/.claude/settings.json`. Any other `{...}` text is refused by `verify`.

**Companion ledger** (`<home>/.skill-mesh-companions.json`, schema_version 1). Written atomically by
the installer and read only by it. It is separate from the Skill Mesh skill ledger, which it never
touches.

| Field | Type | Rule |
|---|---|---|
| `schema_version` | int | 1 |
| `members` | object keyed by `slug` | one entry per member the installer acted on |
| `members.<slug>.tag` | str | the tag installed |
| `members.<slug>.tool` | enum `installed` \| `pre-existing` | `pre-existing` = found on PATH not via this ledger; never uninstalled |
| `members.<slug>.skills` | bool | the member skill installer ran |
| `members.<slug>.setup_write` | bool | `setup_write.install` ran |
| `members.<slug>.hooks` | list | each `{ "name": str, "kind": "file" \| "member", "path": str or null, "sha256": str or null, "owned": bool }` |
| `opt_outs` | object | `{ "no_hooks": bool, "skip_hook": [slug] }` |

**Tripwire shadow-log row** (unchanged by this plan; Step 6 only moves the file). One JSON object
per line: `{"ts": ISO-8601 UTC with milliseconds, "tool": "Bash" | "PowerShell", "rule_id": str or
null (e.g. "TW-SEC-001@v1"), "severity": "none" | "warn" | "fail" | "unknown" | "unavailable",
"observed": str or null}`. `observed` is tripwire's own redacted field; the command text is never
logged.
