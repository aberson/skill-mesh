What I heard

You want confidence that Skill Mesh follows its shared workflow across hosts. You do not expect two LLMs to produce identical implementations or discover the same findings. You asked us to revise constraints that demanded more than that goal, then render the plan for explicit approval.

Required

Correct functional results, required step ordering, complete independent reviews, real runtime evidence, blocked advancement on failures, durable checkpoints and fresh native resume.

Allowed to vary

Valid implementation choices, prose, review findings and judgments. Native tool names and scheduling may vary while preserving the shared obligations.

Exact commits, hashes and receipt bindings remain necessary to establish what was tested. A deterministic aggregate is required for identical normalized findings; identical model-generated findings are not required.

Why this shape

The old acceptance exercise required a reviewer to discover particular planted defects that deliberately incomplete tests missed. That added a model-quality threshold to workflow qualification.

The revised exercise: ordinary functional tests reject the fixed invalid candidates. A fresh developer corrects each candidate, the same tests pass, and then all required real reviewers run. Any actual blocking finding is honored. Review quality is recorded without demanding a prescribed finding.

This preserves an observable failure-and-correction path. It does not claim that a failed test is a reviewer discovery, or that component tests prove the installed native workflow.

Risks and limits

  • A review may miss a defect. M1 demonstrates workflow conformance, not guaranteed defect discovery. Objective failures and unresolved blocking findings still prevent acceptance; record review limitations honestly.
  • Real integration gaps remain. Helpers, actual callers and native resume still need their implementation and live evidence. A rendered proposal or green component tests cannot complete M1.
  • Long test gates still cost time. Their standing obligations are retained. This amendment promises neither a measured speedup nor completion within one overnight window.
  • The active run has fixed limits. Reconcile the current evidence before adoption. A pending gate is not PASS; exhausted iterations and prior qualification failures retain their recorded outcomes.
  • Later shared changes may invalidate acceptance. Requalify affected capability; eventual two-host completion needs one common release with each host satisfying the shared requirements.
