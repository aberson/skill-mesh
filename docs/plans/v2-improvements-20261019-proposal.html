Keep the user journey in charge

Selected ideas for Skill Mesh v2. No new runtime deployment or acceptance claim. The current Ambition → Forge journey remains the immediate delivery target.

What I heard

Incorporate the reviewed seeds, include what would be costly to omit, and defer work that does not help the next useful delivery. Preserve the original intent through planning, build and handoff.

Why this shape

The source has concrete gaps in reviewer independence and auto-lane acceptance. Address these without making the current UAT wait for an expanding improvement program. Reuse existing skills, evidence, stores and measurement tools.

Sequence

  1. Now: preserve the desktop journey; record these requirements and reconcile existing integration work.
  2. Next v2 candidate: fresh reviewers; truthful Done checks; report-only model inventory; private context pointers and intent continuity.
  3. Bounded follow-ups: guard capability probe, sanctioned small-work route, one generative baseline pilot and optional examples.
  4. After current UAT disposition: Forge explanation, observed identity and capacity reporting; larger intake changes only when a real item needs them.

Afterwards: the Toolkit owner selects one bounded implementation item with source scope and acceptance evidence. This roadmap is not a command to dispatch the whole master.

Operator choices

VI-P1: incorporate seeds with agent prioritization. VI-P2: retain drift-ranger and its current/v2 intent hooks; those earlier changes remain untested.

Not in this increment

No automatic model switching, hosted security payload forwarding, blocking Stop hooks, context service, all-skill benchmark campaign, new dashboard, or acceptance inferred from tests. No raw native output in user diagnostics.

Risks

Host behavior must be observed on the installed version before configuration changes. Private paths are private information. Small diffs can be high risk. A printed status token or matching hash does not prove the user journey or complete reviewer reading.
